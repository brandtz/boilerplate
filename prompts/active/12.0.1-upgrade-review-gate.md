# Prompt: Upgrade Review Gate

## Sequence Position
12.0.1 — Review gate after all 9 implementation prompts

## Phase
Review

## Objective
Validate that all 9 accepted recommendations have been correctly implemented, the self-test passes, all new files are consistent with standards, and the boilerplate is ready for production use on the next project (Bulwark).

## Dependencies
- All implementation prompts (3.0.1–11.0.1) complete

## Prerequisites
- Prompt 11.0.1 complete

## Context for the Agent
This is a review gate. It MUST be executed in a **separate conversation session** from the implementation work (per Session Isolation Rule in prompt-lifecycle-standard.md). The reviewer must independently verify each recommendation's acceptance criteria against what was actually delivered.

## Required Reading
- `agents/context/project-charter.md` — success measures
- `agents/context/assumptions.md` — validate assumptions
- `agents/context/constraints.md` — verify constraints respected
- `agents/context/risk-register.md` — check risk mitigations
- `agents/context/decision-log.md` — verify decisions were followed
- `agents/standards/prompt-lifecycle-standard.md` — review gate rules
- `agents/standards/handoff-standard.md`
- `agents/standards/review-signoff-standard.md` — anti-sycophancy rules
- `docs/boilerplate-upgrade-intake.md` — acceptance criteria per recommendation

## Review Scope

### 1. Self-Test Validation
- Run `scripts/validate-boilerplate.sh` — must pass
- Verify it catches at least one type of structural error when triggered

### 2. Acceptance Criteria Verification
For each of the 9 accepted recommendations (1–8, 10), verify:
- All artifacts listed in the intake doc exist
- Templates are well-structured and under line limits
- Context files have correct boilerplate headers
- Updated prompts (00, 01) include the new interview/scaffolding sections
- Updated standards reference new files where specified

### 3. Cross-Reference Integrity
- Every new context file is referenced somewhere (intake prompt, required reading, or a standard)
- No orphaned templates (every template has a corresponding context file or output)
- `.github/copilot-instructions.md` is accurate
- `AGENTS.md` is accurate

### 4. Mandatory Challenger Questions
- What tasks in the charter are NOT covered by implementation prompts?
- What new files exist that are NOT referenced by any standard or prompt?
- What acceptance criteria from the intake doc have NOT been met?
- What would a new agent session look like if started right now — would it find the right files?
- Are there any standards that contradict each other after the updates?

### 5. Risk Register Review
- Are all open risks still relevant?
- Have any risks materialized during implementation?
- Are mitigations adequate?

## Constraints
- This review MUST be in a separate session from implementation
- Must produce at least 3 findings (or a Zero-Finding Justification)
- Must not rubber-stamp — the anti-sycophancy rules in review-signoff-standard.md apply

## Validation Expectations
1. Reviewer runs self-test and reports results
2. Each recommendation's acceptance criteria is checked and documented
3. Findings are grouped by severity (Critical / Major / Minor / Advisory)
4. Sign-off status is explicit: APPROVED, APPROVED WITH CONDITIONS, or REJECTED

## Handoff Instructions
Create a review handoff documenting findings, sign-off status, and any required rework.
