# Prompt: Human Team Mapping

## Sequence Position
10.0.1 — Eighth implementation prompt (Rec 8)

## Phase
Implementation

## Objective
Create the human team mapping context file and template so that real humans are mapped to review gates, approval boundaries, and domain authority. The Orchestrator routes approvals to the correct person rather than to a generic "human sponsor."

## Dependencies
- 9.0.1 (env/secrets standard) complete

## Prerequisites
- Prompt 9.0.1 complete

## Context for the Agent
The boilerplate defines 10+ agent roles but assumes a single "human sponsor" for all approvals. Real projects have multiple humans with different expertise and authority. For example, Bulwark has Matthew (technical authority — architecture, engineering) and Drew (domain authority — field operations, product decisions). Review gates must route to the right person.

- `agents/context/project-charter.md`

## Scope

### E1-S8-T1: Create `agents/templates/team-template.md`
Template with sections for:
- Team Members (name, role/title, domain expertise, authority scope)
- Approval Routing (which review gates require which human, by domain not by name)
- Override/Veto Rights (which agent roles each human can override)
- Escalation Paths (what happens when humans disagree)
- Availability Constraints (timezone, working hours, field time)

### E1-S8-T2: Create `agents/context/team.md`
Copy from template with boilerplate instruction header:
> This file is populated during project intake. Team composition determines approval routing at review gates.

### E1-S8-T3: Update intake prompt (01)
Add team composition interview questions to `prompts/active/01_MASTER_AGENT_PROJECT_INTAKE_PROMPT.md`:
- How many humans are involved?
- What is each person's domain expertise and authority scope?
- Who approves what? (architecture, product, security, operations)
- Are there availability constraints?

### E1-S8-T4: Update review-signoff standard
Add a reference to `team.md` in `agents/standards/review-signoff-standard.md`:
- Review gates that require human approval must specify which human by domain authority, referencing team.md
- The Orchestrator must route domain-specific approvals to the appropriate team member
