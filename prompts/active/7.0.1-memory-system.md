# Prompt: Persistent Memory System

## Sequence Position
7.0.1 — Fifth implementation prompt (Rec 3)

## Phase
Implementation

## Objective
Create a structured persistent memory context file and template so that project-level learnings, resolved ambiguities, and accumulated decisions are consolidated in one place instead of scattered across handoff files. This replaces the need for late-stage agents to read the entire handoff chain.

## Dependencies
- 6.0.1 (skills registry) complete

## Prerequisites
- Prompt 6.0.1 complete

## Context for the Agent
Handoffs preserve session-to-session continuity but accumulate as individual files. Late-stage agents must read a growing chain to reconstruct decisions, patterns, gotchas, and resolved ambiguities. A consolidated memory file solves this. The format must be **structured** (categorised sections with entries), not freeform prose.

## Required Reading
- `agents/context/project-charter.md`
- `agents/context/conventions.md`
- `agents/context/skills.md`
- `agents/standards/prompt-lifecycle-standard.md`
- `agents/standards/handoff-standard.md`
- `docs/boilerplate-upgrade-intake.md` — Recommendation 3 details

## Scope

### E1-S3-T1: Create `agents/templates/memory-template.md`
Template with structured sections:
- Resolved Ambiguities (decision, date, context)
- Patterns That Worked (pattern, where applied, why it works)
- Patterns That Failed (pattern, where tried, why it failed, what replaced it)
- Technical Discoveries (discovery, impact, date)
- Sponsor Preferences (preference, expressed during, date)
- Cross-Cutting Concerns (concern, affected areas, resolution status)

Each section should use a consistent table or list format, not freeform paragraphs.

### E1-S3-T2: Create `agents/context/memory.md`
Copy from template with boilerplate instruction header:
> This file is a living document consolidated by the Repo Knowledge Curator after each phase. It captures project-level learnings so late-stage agents don't need to read the entire handoff chain.

### E1-S3-T3: Update handoff standard
Add a "Memory Candidates" section to `agents/standards/handoff-standard.md`:
- Every handoff should include items the Repo Knowledge Curator should extract into memory.md
- Update the handoff template (`agents/templates/session-handoff-template.md`) with a `## Memory Candidates` section

### E1-S3-T4: Update Repo Knowledge Curator role
If the role file exists in `agents/roles/`, add a responsibility for memory consolidation:
- After each phase, consolidate memory-worthy items from handoffs into memory.md
- Keep memory.md under 200 lines — summarise older entries when approaching the limit
