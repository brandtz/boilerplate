# Prompt: Boilerplate Self-Test Script

## Sequence Position
3.0.1 — First implementation prompt (Rec 10)

## Phase
Implementation

## Objective
Create `scripts/validate-boilerplate.sh` — a structural integrity checker that verifies the boilerplate's file tree, cross-references, and template completeness. This runs first so every subsequent recommendation can be validated after implementation.

## Dependencies
- Intake complete (project charter, assumptions, constraints, risks populated)

## Prerequisites
- Prompt 01 (intake) complete

## Context for the Agent
This is the first implementation prompt of the Boilerplate Process Upgrade v2 project. The self-test script validates that the boilerplate is structurally sound: all files referenced in standards exist, all templates referenced in required-reading chains resolve, all role files have required sections, and the prompt index is consistent with the filesystem. This script will be run after every subsequent prompt to catch regressions.

The script must be cross-platform: it runs in Git Bash on Windows and native bash on macOS/Linux. Keep to POSIX-compatible constructs.

## Required Reading
- `agents/context/project-charter.md` — project scope and success measures
- `agents/context/assumptions.md` — assumption A8 (cross-platform)
- `agents/context/constraints.md` — constraint C7 (self-test runs first)
- `agents/standards/prompt-lifecycle-standard.md` — governance and close-out rules
- `agents/standards/handoff-standard.md` — handoff requirements
- `docs/boilerplate-upgrade-intake.md` — Recommendation 10 details

## Scope

### E1-S10-T1: Create `scripts/validate-boilerplate.sh`
The script must check:
1. **Required directories exist:** `agents/`, `agents/context/`, `agents/standards/`, `agents/templates/`, `agents/roles/`, `agents/workflows/`, `prompts/`, `prompts/active/`, `prompts/archive/`, `dashboard/`
2. **Required context files exist:** `project-charter.md`, `assumptions.md`, `constraints.md`, `risk-register.md`, `decision-log.md`, `status-dashboard.md`, `product-brief.md`, `architecture-overview.md`
3. **Required standards exist:** All `.md` files in `agents/standards/` are non-empty (> 3 lines)
4. **Required templates exist:** All `.md` files in `agents/templates/` are non-empty (> 3 lines)
5. **Role directories have content:** Each subdirectory in `agents/roles/` contains at least one `.md` file
6. **Prompt index consistency:** Every `.md` file in `prompts/active/` has a matching row in `prompts/index.md`
7. **Cross-reference validation:** File paths referenced in `agents/standards/required-reading-standard.md` (if it exists) resolve to actual files
8. **No orphaned handoffs:** Every handoff in `agents/handoffs/` (if any) is referenced by at least one prompt's frontmatter or the index

Output format:
- `PASS: <check description>` for each passing check
- `FAIL: <check description> — <details>` for each failing check
- Exit code 0 if all checks pass, exit code 1 if any fail
- Summary line at end: `N/N checks passed`

### E1-S10-T2: Create smoke test fixture
Create `tests/smoke/` containing:
- `tests/smoke/README.md` — explains what the smoke test is and how to use it
- `tests/smoke/sample-project-idea.md` — a minimal project description that could be fed into intake prompt 01

The smoke test is a manual validation fixture, not an automated runner. Its purpose is to provide a known-good project idea for testing the intake pipeline.

### E1-S10-T3: Update Standards Guardian role
Add a "Meta-Review" responsibility to the Standards Guardian role file (`agents/roles/orchestration/standards-guardian.md`):
- After any boilerplate structural change, the Standards Guardian must run `scripts/validate-boilerplate.sh`
- The self-test must pass before the change is committed

## Constraints
- POSIX-compatible shell only (no bashisms like `[[`, arrays, or `shopt`)
- No external dependencies beyond standard Unix tools (`find`, `grep`, `wc`, `sed`, `awk`)
- Script must be executable (`chmod +x`)
- Must work from the repo root directory

## Validation Expectations
1. Run `scripts/validate-boilerplate.sh` from the repo root — it should pass with the current boilerplate state
2. Temporarily rename a required file and re-run — it should fail with a clear error message
3. Restore the file and confirm the script passes again

- All files created and modified
- Self-test output from a clean run
- Any assumptions made about the current directory structure
- Any risks identified during implementation
