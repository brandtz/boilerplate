# Prompt: Skills and Capabilities Registry

## Sequence Position
6.0.1 — Fourth implementation prompt (Rec 4)

## Phase
Implementation

## Objective
Create the skills/capabilities context file and template as a **separate** artifact from conventions (per sponsor constraint C5). This file declares what tools, APIs, MCP servers, and environment capabilities are available to agents in the current project.

## Dependencies
- 5.0.1 (AGENTS.md) — AGENTS.md should reference skills.md

## Prerequisites
- Prompt 5.0.1 complete

## Context for the Agent
Agents don't know what tools are available to them. A Copilot agent in VS Code has different capabilities than a cloud agent. An agent with MCP server access has different capabilities than one without. This file declares the available toolset so architecture and implementation decisions can be grounded in reality.

**Key constraint:** Skills/capabilities must remain separate from conventions. Conventions are stable per-project; skills shift per environment and toolset.

## Scope

### E1-S4-T1: Create `agents/templates/skills-template.md`
Template with sections for:
- Agent Environment (VS Code local, cloud, CI runner)
- MCP Servers (name, what it provides, auth requirements)
- CLI Tools (name, version, purpose)
- APIs — Internal (name, endpoint pattern, auth)
- APIs — External (name, purpose, SDK, auth)
- AI Model Access (which models, what for, rate limits)
- File System Boundaries (what the agent can read/write)
- Environment Constraints (no Docker, static export only, etc.)

### E1-S4-T2: Create `agents/context/skills.md`
Copy from template with boilerplate instruction header:
> This file is populated during project intake. Skills are validated during architecture review.

### E1-S4-T3: Update intake prompt (01)
Add a skills interview section to `prompts/active/01_MASTER_AGENT_PROJECT_INTAKE_PROMPT.md`:
- Ask the sponsor about available tooling, MCP servers, agent environment
- Populate `agents/context/skills.md` from the answers
